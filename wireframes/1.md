# Chorus: Structured Language Learning — Implementation Plan
**Scope:** English ↔ Spanish, CEFR A1–B2, integrated into the existing chat/translation/grammar/AI-tutor product.
**Audience:** Engineering agent implementing this feature set.

---

## 1. Design Philosophy (the science, briefly)

Every feature below traces back to one of these five research-backed principles. When making implementation trade-offs, default to whichever choice serves these:

1. **Comprehensible Input + Output (Krashen / Swain).** People acquire language fastest from input slightly above their level (i+1) *and* from being pushed to produce output and notice gaps in it. Chorus already generates both — real messages (input) and replies (output) — so the learning layer should be built as a layer *on top of* real conversation, not a separate app bolted alongside it.
2. **Spaced Repetition + the Testing Effect.** Retrieval practice spread over increasing intervals beats re-reading or massed review by a wide margin. All vocabulary/grammar review must run through a spaced-repetition scheduler, not a static "my words" list.
3. **Desirable Difficulty / Interleaving.** Mixing skills (vocab, grammar, listening) and item types in one review session produces better long-term retention than blocked drilling of one type at a time.
4. **CEFR "Can-Do" Framing.** Learners stay motivated when progress is expressed as concrete real-world abilities ("I can order food," "I can describe my week") rather than abstract levels. Use CEFR descriptors as the backbone of the curriculum *and* the UI copy.
5. **Self-Determination Theory (motivation).** Sustained daily practice needs autonomy (choice of content/pace), competence (visible progress, achievable difficulty), and relatedness (social/community — this is where the chat context and future marketplace are a genuine advantage over Duolingo-style apps).

**Core product thesis:** Chorus's unique edge is that learners are already producing and receiving real, personally meaningful messages. Competitors manufacture example sentences; Chorus's users generate their own corpus every day. The structured-learning layer should mine that live conversation stream for vocabulary, grammar points, and practice material, and use CEFR structure only to sequence and gap-fill what real conversation doesn't naturally cover.

## 2. User Personas (Launch Scope)

- **Persona A — "Maya," English L1 learning Spanish.** Talks daily with a Spanish-speaking partner/friend/colleague via Chorus. Wants to rely less on auto-translation over time. Motivated by relationships, not exams.
- **Persona B — "Diego," Spanish L1 learning English.** Same shape, mirrored. Note: content, example sentences, and grammar contrast notes must be authored/validated separately for each direction — Spanish→English grammar traps (ser/estar, subjunctive, gendered nouns) are not symmetric with English→Spanish traps (phrasal verbs, articles, do-support).

Both personas share one property that should shape the architecture: **the learner and the "answer key" are asymmetric.** A Spanish item shown to Maya needs an English-anchored explanation; the same Spanish item shown to a native Spanish speaker studying English needs no such scaffolding. So content and SRS cards must always be modeled as `(target_lang, base_lang)` pairs, never as language-agnostic global content.

## 3. Curriculum Structure (CEFR Backbone)

### 3.1 Launch scope
Launch with **A1 → B2** (four levels). C1/C2 come later — at that stage users are typically better served by pure conversation + light grammar analysis than by structured lessons, and building C-level content is expensive relative to the user base that reaches it.

### 3.2 Unit structure
Each CEFR level is broken into ~10–14 **Units**, each built around a *communicative goal* (a can-do statement), not a grammar topic:

```
Level: A1
Unit 4: "I can talk about my daily routine"
  ├─ Core vocabulary set (~25-35 lemmas)
  ├─ 1-3 target grammar points (e.g., present tense regular -AR verbs, reflexive verbs)
  ├─ 4-6 micro-lessons (2-4 min each): intro, examples, contrast w/ base language, mini-check
  ├─ Practice session (mixed drills, generated + SRS review)
  ├─ "Real talk" prompt: a suggested conversation starter to use in an actual Chorus chat
  └─ Can-do checkpoint (short assessment; unlocks next unit)
```

Grammar points and vocabulary sets should be tagged with a **CEFR grammar/lexical inventory** (build from public CEFR reference inventories for Spanish — e.g. Instituto Cervantes' *Plan Curricular* — and for English — e.g. the English Vocabulary Profile / English Grammar Profile from Cambridge). This tagging is the single most important data asset in the system, because it's what lets you auto-classify real chat messages by level later (Section 5).

### 3.3 Placement
New learners take a 5–8 minute adaptive placement test (see 8.2) to drop them into the right unit instead of forcing everyone through A1.

## 4. The Daily Practice Loop (retention engine)

This is the feature most correlated with actual language gain, so give it the most product polish.

**Daily session = 1 screen, ~5–10 minutes, always available, one tap from the chat tab.**

Composed dynamically each day from three sources, interleaved (principle #3 above):

1. **SRS review (priority, always first):** every vocabulary/grammar card due today, per the spaced-repetition scheduler (Section 6).
2. **New unit content:** 1 micro-lesson + a few new items, if the learner is progressing through structured units.
3. **Mined-from-chat practice:** words/phrases/grammar structures pulled automatically from the learner's *actual recent conversations* (Section 5) — this is the differentiator vs. Duolingo/Babbel and should be visually called out ("From your chat with Diego yesterday").

Session ends with a single completion state (streak +1, XP, mini can-do progress bar) — avoid stacking multiple gamification systems; one clear loop beats five weak ones.

**Notification strategy:** one daily reminder, time-of-day personalized to when the user is usually active in chat (not a fixed push time), skip-day forgiveness (streak freeze, 1-2 per month) — punitive streak mechanics measurably increase churn and should be avoided.

## 5. Mining the Chat Stream (Chorus's actual moat)

This is new relative to typical language apps and should be built as a background pipeline, not a per-tap feature only.

**Pipeline, per translated message:**
1. Run existing grammar-analysis step (already in product) → structured parse (POS tags, dependency/constituency info, identified constructions).
2. Match detected constructions against the CEFR grammar inventory tags → attach `grammar_point_id`s with confidence scores.
3. Extract lemmas not already in the user's known/learning vocabulary → candidate vocab items.
4. Score each candidate for "teachability" (frequency rank, CEFR level vs. user's level, whether it's a cognate/false-friend, idiomaticity) to avoid surfacing noise (proper nouns, typos, slang unless flagged as such).
5. Surface the top items into: (a) the tap-to-save UI (Section 7), (b) the next daily session's "from your chat" slot, (c) optionally an end-of-conversation nudge ("3 new words from this chat — review them?").

This turns every conversation into curriculum content automatically and is what differentiates the "structured learning fastest way possible" pitch — the content is never generic, it's the learner's own life.

## 6. Vocabulary System & Spaced Repetition

### 6.1 Tap-to-save
- Tap any word in a message (sent or received, original or translated) → bottom sheet with: lemma, part of speech, definition (base-language), the word *in that exact sentence's context*, audio/TTS, CEFR level tag, and an "Add to practice" button.
- Saved word becomes a **VocabCard**, stored with the originating message as its example sentence (real context > generated example — use generated examples only as a fallback for words saved outside a chat context, e.g. from a lesson).
- Support multi-word expressions (phrasal verbs, collocations, idioms) as first-class card types, not just single lemmas — this matters especially for English (phrasal verbs) and Spanish (idiomatic reflexive/preposition combos).

### 6.2 Scheduler
- Implement a modern spaced-repetition algorithm — **FSRS (Free Spaced Repetition Scheduler)** is recommended over legacy SM-2: it fits difficulty/retention curves per-user from review history and consistently outperforms SM-2 in retention-per-minute-studied in published comparisons. If engineering time is tight for v1, ship SM-2 first (simple, well understood) with the data model already designed to support swapping in FSRS later (store raw review logs: card_id, timestamp, grade, response_time — FSRS needs this history to fit its model, so log it from day one even before you use it).
- Card states: New → Learning → Review → (Relearning on lapse) → Mature.
- Review item types per card, rotated for interleaving: recognition (see word, pick meaning), recall (see meaning, produce word), listening (audio → meaning), cloze-in-context (fill blank in the original example sentence), and — where the AI tutor is involved — a short AI-generated "use it in a new sentence" production check.

### 6.3 "My Vocabulary" hub
A persistent, searchable list of all saved words/phrases with: status (new/learning/mastered), source (which chat/lesson), example sentence, and a manual "practice now" override outside the daily queue.

## 7. AI Tutor Integration

Treat the AI Tutor as the connective tissue between free chat and structured content, not a separate chatbot.

**Trigger points:**
- From any message: "Explain this grammar," "Give me 3 more examples like this," "Why not [alternative phrasing]?", "Make this a flashcard."
- From a grammar-analysis result: tutor can expand any detected construction into a mini-explanation anchored to the user's base language (contrastive explanation — e.g., for an English speaker: "Spanish marks this with subjunctive because the main clause expresses doubt; English usually doesn't mark this at all").
- From SRS review: on a wrong answer, one-tap "ask tutor why" instead of just showing the correct answer — turns failure into a teaching moment (important for retention — corrective feedback with explanation outperforms bare answer-reveal).

**Flashcard generation:** user selects any span of a message → "Create flashcard(s)" → AI Tutor proposes a card (word/phrase, definition, example, optionally a cloze variant and a grammar-point tag) → user edits/confirms → enters the SRS queue via the same pipeline as tap-to-save. Always require a confirm step; never silently auto-add AI-generated cards to avoid low-quality/incorrect items polluting the deck.

**Guardrails:** tutor explanations should always be traceable to the CEFR grammar inventory tag where possible (consistent terminology across lessons and tutor answers), and should be level-aware (don't explain B2 subjunctive nuance to an A1 learner who asked a simple vocabulary question).

## 8. Assessment & Adaptivity

### 8.1 Ongoing checkpoints
End of each unit: short can-do checkpoint (8-12 items, mixed skills) — pass unlocks next unit; near-miss triggers a short targeted review instead of a hard gate (avoid punishing users out of the app).

### 8.2 Placement test
Adaptive, ~20-30 items spanning A1-B2 vocabulary/grammar recognition + one short passage comprehension check + optional short free-response rated by the AI tutor. Output: starting unit + an initial "known vocabulary" seed list (so the SRS system doesn't waste reviews on words the user already knows) + optionally seed from analyzing the user's *existing* chat history if they're not a brand-new user (bootstraps mined vocabulary instantly).

### 8.3 Progress model
Track two parallel signals, shown separately in UI:
- **Structured progress:** unit/level completion (CEFR-legible: "A2 → 62%").
- **Practical fluency signal:** derived from real chat behavior — declining reliance on auto-translation, vocabulary breadth actually used unprompted in messages, grammar-analysis error rate trend over time. This is the "am I actually getting better at real communication" metric and is arguably more motivating than lesson completion %, and it's data only Chorus can produce.

## 9. Data Model (starting point for the agent)

```
User(id, base_lang, target_lang, cefr_level_estimate, streak_count, ...)
VocabCard(id, user_id, lemma, target_lang, pos, definition, example_sentence,
          example_source_message_id?, cefr_level, srs_state, srs_due_at,
          ease/difficulty (algorithm-specific), created_from ENUM[tap, tutor, lesson])
ReviewLog(id, card_id, timestamp, grade, response_time_ms, item_type)
GrammarPoint(id, lang, cefr_level, name, description, contrast_notes[base_lang])
UserGrammarMastery(user_id, grammar_point_id, confidence_score, last_seen_at)
Unit(id, lang_pair, cefr_level, order, can_do_statement, grammar_point_ids[], vocab_ids[])
LessonItem(id, unit_id, type ENUM[micro_lesson, drill, checkpoint], content_json)
UserUnitProgress(user_id, unit_id, status, score, completed_at)
MinedItem(id, user_id, source_message_id, candidate_lemma_or_grammar_id,
          teachability_score, status ENUM[suggested, saved, dismissed])
```

Keep `VocabCard` and `GrammarPoint` always scoped by `(target_lang, base_lang)` as discussed in Section 2 — never store a "definition" without knowing which base language it's explained in.

## 10. Phased Roadmap

**Phase 1 — MVP (fastest path to a defensible daily-use product)**
- Tap-to-save vocabulary + basic SRS (SM-2) + "My Vocabulary" hub
- Daily practice loop combining SRS review + chat-mined items (skip structured units initially — ship the mining pipeline first since it's the differentiator and reuses the existing grammar-analysis feature)
- Basic streak/notification system

**Phase 2 — Structured Curriculum**
- Full A1-B2 unit content for both language directions (this is a content production project — plan for professional translators/pedagogy reviewers, not just LLM generation; use LLM to draft, native-speaker CEFR-trained reviewers to validate)
- Placement test
- Unit progress UI, can-do checkpoints

**Phase 3 — AI Tutor Deepening**
- In-context "explain/more examples/why not X" actions
- AI flashcard generation with confirm-step
- Tutor-guided review feedback on SRS misses
- Swap SM-2 → FSRS using accumulated ReviewLog data

**Phase 4 — Social & Marketplace**
- Group chats scoped to a language/level (peer practice — strong motivational lever per SDT's "relatedness")
- Teacher marketplace: profile/verification, private lesson booking, group lesson hosting, in-app payments
- Teacher-side tools: assign structured units/custom vocab lists to students, see student SRS/mastery data (with consent) to prep lessons — this is a natural extension of the data model above and a genuine differentiator vs. iTalki/Preply, which have no automatic mining or SRS integration with real conversations.

## 11. Metrics to Track From Day One

- D1/D7/D30 retention on the daily practice loop specifically (leading indicator of actual gains)
- SRS review accuracy trend per user (proxy for real retention)
- % of daily-session content sourced from chat-mining vs. structured units (validates the differentiator)
- Reliance-on-translation trend (are users tapping "show original" / reading target-language text unassisted more over time)
- Unit completion → checkpoint pass rate (content difficulty calibration signal)

---

## 12. Key Build Risks / Notes for the Agent

- **Content quality is the bottleneck, not the algorithm.** A mediocre SRS scheduler with excellent, correctly-leveled, native-reviewed content will outperform a perfect FSRS implementation with sloppy content. Budget accordingly — get native speakers/pedagogy reviewers for both directions before scaling unit count.
- **Don't build two parallel vocabulary systems.** Tap-to-save, AI-tutor flashcards, and structured-lesson vocabulary must all resolve into the *same* VocabCard/SRS pipeline, or you'll end up with three weak review systems instead of one strong one.
- **Log review data even before you need it** (raw grade/timestamp/response-time), so a future FSRS migration doesn't start from zero.
- **Keep the daily session short and singular.** One unified session beats separate "vocab practice," "grammar practice," and "lesson" entry points — interleaving is a feature, not a compromise.
