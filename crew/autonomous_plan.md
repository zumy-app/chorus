## Phase 9 — SRE: Performance, Scalability & NFRs

**Owner:** sre engineer
**QA:** qa_engineer verifies NFR compliance

### 9.1 Layer 4 Load Balancer (leastconn)
- Configure HAProxy L4 TCP mode with leastconn algorithm
- Fronts stateless chat-server replicas
- No sticky sessions (state in Postgres/Redis only)
- Test: Spin up 2+ backend replicas, verify LB distributes connections

### 9.2 Redis Connection Registry
- Implement ws:registry:{userId} → {serverID, connID} mapping
- Written on WebSocket connect, cleared on disconnect
- TTL heartbeat to handle stale connections
- Test: Connect user, verify registry entry, disconnect, verify cleanup

### 9.3 Cross-Server Message Routing
- Recipient on server S2 → S1 persists to Postgres, looks up registry
- Publishes to server:{S2} Redis channel → S2 delivers + marks delivered
- Test: Two users on different servers, verify message delivery round-trip

### 9.4 Horizontal Scalability
- Chat servers fully stateless (no in-memory session state)
- All state in Postgres (durable) and Redis (cache/pubsub)
- Test: Scale to 3+ replicas, verify no message loss

### 9.5 Load & Soak Testing
- Artillery config: 1k concurrent WS connections, 50 msg/s, 24h drain
- Verify message loss = 0
- NFR compliance: p95 latency < 200ms, uptime target
- Test: Run artillery load + soak profiles, verify results

### 9.6 NFR Compliance
- NFR-17: No secrets in repo
- NFR-22: Mobile-first, web parity
- NFR-23: Data retention + GDPR
- NFR-24: Rate limiting on all endpoints
- NFR-25: Observability (metrics, traces, dashboards)
- NFR-26: CI/CD quality gates
- Test: Automated NFR compliance check script

**Phase 9 Gate:** L4 LB + Redis registry + cross-server delivery proven. Soak test passes with zero loss.
